# דרישות ההגשה והכנה להגנה אישית

## מקור ההנחיות הנוכחיות

המיפוי הנוכחי מבוסס על נוסח ההנחיות העדכני של יריב שצירף המשתמש בשיחה ב־3.11.2026 כטקסט, ונקרא בעדכון זה. הקובץ המקורי „הוראות של יריב.docx” אינו זמין, אך אין פירוש הדבר שנוסח ההוראות העדכני חסר. זהו מיפוי של המקורות והמימוש, לא אישור המרצה לקבלת הפרויקט.

- מגישים **קישור למאגר GitHub ציבורי** בתיבת ההגשה במכללה, עד 5.11.2026 בשעה 10:00; לא ZIP או קבצים.
- **אין סרטון.** נדרשת **הגנה אישית של כ־7 דקות**, עם הפרויקט פתוח בעורך ורץ מקומית. עונים באופן עצמאי, ללא סוכן או חיפוש.
- לפי הנוסח שנמסר בוחרים שיבוץ ל־6.11 מ־09:00 או ל־8.11 מ־16:00, בכיתה או ב־Zoom. אין תיעוד שהסטודנט נרשם או ניגש להגנה.
- ההנחיות העדכניות מחלקות את הציון למוצר 60, תהליך 20 והגנה 20. הסרטון והשאלון שבמיפוי הישן אינם רשימת חובה נוכחית; השאלות שבו יכולות לשמש לתרגול בלבד.

## דרישות והממצאים המאומתים

העמודה „ראיה” מציינת קוד או תוצאות מתועדות; אין כאן הרצה חדשה או טענה שכל דרישות ההגשה הושלמו.

| דרישה נוכחית | ראיה ומצב |
|---|---|
| React + Vite + TypeScript; build תקין | קיימים בקוד וב־package.json; build עבר בהרצות המתועדות. בדיקת dev ללא שגיאות קונסול בסביבת ההגנה עדיין נדרשת לפני ההגשה. |
| טיפוסים למידע ול־props, ללא any | מבנה Song, props ומצב תגובת ההמרה מטופסים; נתוני JSON נבדקים מ־unknown. אין כאן סריקת טיפוסים חדשה. |
| לפחות ארבעה רכיבים נפרדים שאינם עמודים | בין היתר SongList, SongCard, SongPlayer, FavoriteButton ו־PhotoGallery, בקבצים נפרדים. |
| React Router, Link/NavLink, useParams, map ו־key | רשימת שירים ועמוד /songs/:songId; גם רשימת תאריכים ו־/memorial-dates/:year. הקטלוג מקומי; אין לטעון שהוא נשלף מ־API. |
| שני עמודים נוספים עם פעילות/מידע | קיימים חידון פעיל וגלריה אינטראקטיבית באודות, לצד הבית ואזור התאריכים. קבלת השילוב הזה כשני עמודים נוספים טעונה הכרעת המרצה; אודות טקסטואלי בלבד אינו מספיק לפי ההוראות. |
| API חינמי ללא מפתח, fetch ב־useEffect, טעינה/שגיאה/מידע | Hebcal converter בעמוד פרטי התאריך. fetch אמיתי מהאתר אומת בשלב המימוש. רשימת השנים עצמה מקומית — ראו פער ההתאמה להלן. iframe אינו תחליף ל־fetch. |
| חיפוש או סינון | חיפוש בשם/תיאור שירים וסינון מועדפים. |
| לפחות חמש בדיקות Vitest ו־Vitest UI | 14 בדיקות לוגיקה עברו; UI אומת. npm test ו־npm run test זהות, והממשק מופעל ב־npm run test:ui. |
| CSS והתאמה למסך צר | CSS מקומי, RTL ובדיקות תצוגה בשני רוחבי חלון; אין בכך בדיקה בכל מכשיר או אישור נגישות מלא. |
| בדיקות דפדפן משלימות | תוצאה אחרונה: 50 בדיקות Playwright, 25 לכל רוחב 1280 ו־390; נדרשה עצירה ידנית של preview בסיום. זהו אימות משלים, לא תחליף ל־Vitest. |
| README, PRD, tasks, PROMPTS | README בשורש ושאר המסמכים ב־docs עם קישורים. נוספו תרחישי קבלה ותנאי Done when; עדכון זה עדיין ממתין לאישור ולשמירה. PROMPTS חלקי. |
| מאגר ציבורי ו־commits הדרגתיים | לפי האימות האחרון המאגר ציבורי, ושני הענפים המרוחקים מצביעים ל־60b8a1e. commits של API, Vitest והתיעוד כבר הועלו. האתר עצמו לא נפרס לציבור. |

## פערים שדורשים השלמה או אישור מפורש של המרצה

1. **תנאי המשך בפרויקט קיים — פער קריטי:** ההנחיות דורשות את כל הפרומפטים המקוריים מתחילת הפרויקט, לפי הסדר, לצד commits הדרגתיים. ב־[PROMPTS.md](PROMPTS.md) יש 35 הודעות מקור מ־14.10 ומ־2–3.11; המקוריים מ־7–12.10 עדיין חסרים. סיכומים היסטוריים אינם ממלאים דרישה זו. נוסח ההנחיות מפנה למאגר חדש מהתבנית אם התנאי חסר; אין כאן אישור לחריגה, ויש להשלים את המקורות או לקבל הוראה מפורשת מיריב.
2. **מרכזיות ה־API במבנה Master–Detail:** המידע הלועזי מגיע בפועל מ־Hebcal, אך רשימת השנים ורשימת השירים מקומיות. סדר העבודה המומלץ בהנחיות מתאר החלפת רשימה מקומית ב־fetch. יש לברר אם היקף ההמרה הנוכחי מתקבל; אין להציג את ההתאמה כמוכרעת.
3. **שני העמודים הנוספים:** לתעד ולהדגים את פעילות החידון והגלריה/עמודי המידע ולקבל הכרעה אם הם עומדים בהיקף הנדרש. לא נוספו עמודים במסגרת עדכון זה.

- אישור, commit ו־push של עדכון המסמכים הנוכחי; `60b8a1e` כולל את שלב התיעוד הקודם בלבד.
- אימות סיום אוטומטי של Playwright ללא עצירה ידנית, ובדיקת dev/קונסול בסביבת ההגנה. ראו [VALIDATION.md](VALIDATION.md).
- השלמת היסטוריית הפרומפטים או בירור דרך ההמשך מול המרצה, והכרעת פערי API/עמודים נוספים.
- פתיחת קישור המאגר בגלישה בסתר לקראת ההגשה, שליחתו בתיבת ההגשה, שיבוץ והכנה להגנה האישית. פעולות אלו אינן מוכחות מעצם ה־push.

# התאמה לסילבוס והכנה להגשה

המיפוי מבוסס על הסילבוס שצורף. הוא מציין שרשימת הנושאים היא מפת דרכים ושיפורסמו הנחיות מפורטות למטלה בנפרד. המסמך אינו אישור של המרצה ואינו מחליף הנחיות אלה.

החלוקה והסרטון המוצגים בהמשך נשמרים מתוך המיפוי ההיסטורי. „הוראות של יריב.docx” אינו זמין בבדיקה הנוכחית; משקלי הציון, משך ההצגה וכללי ההגשה דורשים אימות מול ההוראות המקוריות.

## המוצר — 60%

| נושא | שימוש בפרויקט |

## הבנה — 20%

בסילבוס נדרש סרטון של כ־5 דקות ושאלון אישי. אלו פעולות של הסטודנט שלא בוצעו בידי הסוכן. צריך להסביר במילים שלך ולהיות מסוגל לשנות את הקוד.

תוכנית מוצעת לסרטון:

1. 0:00–0:40: קהל היעד והבחירה במוזיקה ובסיפור החיים.
2. 0:40–1:40: הדגמת חיפוש, נגן, אודות ומועדפים.
3. 1:40–2:30: App, React Router, Song וה־props של SongCard.
4. 2:30–3:30: useState, filter/map, Context ו־localStorage.
5. 3:30–4:20: commits, PRD ויומן AI.
6. 4:20–5:00: בדיקות ומגבלות, ושינוי קטן שאתה מבין, כגון תיאור שיר.

שאלות לתרגול:

- מה ההבדל בין props לבין state, ואיפה הם מופיעים?
- למה המועדפים נמצאים ב־Provider ולא בכל עמוד בנפרד?
- למה id משמש key במקום מספר סידורי?
- מה ההבדל בין Context ל־localStorage?
- מה קורה בחיפוש ללא תוצאות ובכתובת שיר חסרה?
- למה צריך fallback בשרת עבור רענון עמוד פנימי?
- מה הבדיקות מאמתות לגבי YouTube, ומה הן לא מאמתות?
