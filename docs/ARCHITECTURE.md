# איך האתר עובד

## מהקובץ למסך

index.html מגדיר עברית וכיוון RTL ומכיל את האלמנט root. הקובץ src/main.tsx מחבר אליו את React ומרנדר את App. רכיב App מחזיק את הכותרת, הניווט, התוכן והתחתית שמשותפים לכל העמודים.

React Router בוחר עמוד לפי הכתובת. לחיצה על Link משנה את התוכן בתוך היישום בלי טעינה של מסמך HTML חדש. רענון כן פונה לשרת, ולכן בשרת ציבורי צריך להחזיר index.html גם עבור כתובות פנימיות.

## תוכן ו־TypeScript

src/data/songs.ts מכיל interface בשם Song ורשימה מטיפוס Song[]. כל פריט דורש id, title ו־description; youtubeId ורשימת links הם אופציונליים בטיפוס. בדיקת TypeScript מזהה שדות חסרים וטיפוסים לא מתאימים, אך לא מאמתת שתוכן חיצוני זמין.

SongCard, SongPlayer ו־FavoriteButton מקבלים שיר באמצעות props מטופסים. כך משתמשים באותו כרטיס בבית וברשימה בלי לשכפל את תוכנו.

## חיפוש ורשימות

SongList מחזיק query ו־favoritesOnly באמצעות useState. האירוע onChange מעדכן את המצב לפי מה שמקלידים. הפונקציה filterSongs ב־src/lib/filterSongs.ts מנקה רווחים בקצוות ובוחרת באמצעות filter שירים ששמם או תיאורם מכילים את הטקסט. סינון המועדפים הוא תנאי נוסף באותה פעולה. הלוגיקה חולצה לצורך בדיקות יחידה ללא שינוי התנהגות.

התוצאות מחושבות מחדש מהנתונים ומהמצב בכל רינדור, ולא נשמרות כעותק נוסף ב־state. map הופך כל תוצאה לכרטיס. המזהה הקבוע משמש key כדי ש־React יזהה פריטים גם כשהרשימה משתנה.

## מועדפים משותפים

FavoritesProvider נמצא מעל העמודים ולכן אינו נעלם כשעוברים ביניהם. הוא מחזיק מערך מזהים באמצעות useState ומספק אותו ואת toggleFavorite דרך Context. useFavorites מאפשר לרכיבים לקרוא את המצב המשותף.

toggleFavorite משתמש בעדכון פונקציונלי: מקבל את המערך הקודם ויוצר מערך חדש באמצעות filter להסרה או פריסה להוספה. לא משנים את המערך הקודם במקום.

useEffect שומר את המערך ב־localStorage אחרי שינוי. בקריאה הראשונה מוודאים שהמידע הוא מערך ושמזהי השירים קיימים. מידע פגום נופל לרשימה ריקה. אחסון חסום אינו מפיל את האתר, ומוצגת הודעה שהבחירה לא תשרוד רענון.

localStorage שייך לדפדפן ולכתובת האתר, כולל הפורט. Context אינו מסד נתונים; אין סנכרון בין מכשירים או בין לשוניות פתוחות.

## עמוד השיר

SongPage קורא songId מהכתובת באמצעות useParams ומוצא את השיר באמצעות find. מזהה לא מוכר מציג הודעה וקישור לרשימה. זהו מבנה Master–Detail עם נתוני שירים מקומיים. אם יש youtubeId, SongPlayer יוצר iframe של YouTube וקישור ישיר חלופי. אחרת הוא מעדיף Spotify ואם אין קישור כזה בוחר קישור אלבום לפי נתיב /albums/ עבור נגן Amazon. מוצגים גם קישורי האזנה. חלק מהקישורים מובילים לאלבום ומסומנים כך; אין הבטחה לניגון השיר הנבחר. האתר אינו מוריד את המדיה ואינו מפעיל אותה אוטומטית ביוזמתו.

## תאריכים לזיכרון

MemorialDatesPage מציג שש שנים מתוך src/data/memorialYears.ts. Link מוביל ל־/memorial-dates/:year; MemorialDatePage קורא את השנה באמצעות useParams ומוודא שהיא נתמכת. הרשימה מקומית; פרטי ההמרה נשלפים מ־https://www.hebcal.com/converter באמצעות fetch בתוך useEffect עבור hy, hm=Tishrei, hd=30, h2g=1, cfg=json ו־strict=1.

מצב מאוחד מטופס מבחין בין loading, error ו־success. התגובה נקראת כ־unknown ומאומתת ב־isConvertedDate שב־src/lib/convertedDate.ts: שנה ויום עברי מבוקשים, שדות מספריים ותאריך לועזי שאינו גולש לחודש אחר. זו בדיקת מבנה ותקינות לוח לועזי, לא אימות עצמאי של אלגוריתם ההמרה. יש כפתור ניסיון נוסף, timeout של 15 שניות, AbortController וניקוי בעת מעבר עמוד כדי למנוע עדכון מבקשה ישנה.

אין שימוש ב־Yahrzeit API. מוצגת המרה בלבד של ל׳ בתשרי, עם קרדיט ל־Hebcal והבהרה שאין זו קביעת מועדי אזכרה לפי מנהג המשפחה.

## עיצוב ונגישות

Flexbox משמש לניווט ולכרטיסים, ו־media query מתאים ריווח למסכים קטנים. השתמשנו ב־header, nav, main, section, article ו־footer. לכל עמוד כותרת ראשית ולחיפוש תווית.

כפתור המועדפים מציין מצב באמצעות aria-pressed. תוצאות החיפוש מתעדכנות באזור role=status. קישור דילוג מוביל לתוכן. RouteFocus מעדכן כותרת לשונית, גלילה ומיקוד באמצעות useEffect בעת מעבר עמוד.

## בדיקת שינוי

הריצו npm run lint, npm test ו־npm run build. npm test ו־npm run test בודקים טיפוסי בדיקות ומריצים 14 בדיקות יחידה ב־Vitest; npm run test:ui פותח UI במצב מעקב. vitest.config.ts משלב את תצורת Vite ואוסף tests/unit/**/*.test.ts בלבד. npm run test:e2e בונה production ומריץ 50 בדיקות Playwright — 25 לכל רוחב מסך (1280 ו־390); playwright.config.ts אוסף קובצי ‎*.spec.ts בלבד. שינוי נתוני שירים עשוי לדרוש עדכון בדיקות התוכן. זמינות נגנים ו־fetch אמיתי נבדקים בנפרד מתשובות הרשת המדומות. ראו [תוצאות ומגבלות](VALIDATION.md).

היקף הבדיקות מאומת גם בקבצים: 21 תרחישים ב־tests/site.spec.ts ועוד 4 ב־tests/memorial-dates.spec.ts, בשני פרויקטי חלון. בתוצאות האחרונות כל 50 הבדיקות עברו, אך סיום התהליך דרש עצירת שרת preview ידנית; אין בכך אישור לסיום אוטומטי תקין בכל סביבה. 14 בדיקות Vitest עברו בהרצה המתועדת האחרונה. לא הורצו בדיקות תוכנה מחדש במסגרת עדכון תיעוד זה.
