# תיעוד פרומפטים ועבודה עם AI

## מקור ומגבלות

מקור התיעוד הוא הודעות המשתמש ותוצאות הכלים בשיחת Codex הנוכחית, קוד הפרויקט והיסטוריית Git. כל סעיפי „מה התבקש” להלן הם **סיכומים, לא ציטוטים של הפרומפט המקורי**, גם כאשר ההודעה המלאה זמינה בשיחה. מסמך זה אינו תמלול מלא ואינו משחזר פרומפטים שאבדו. לא הומצאו תאריכי שיחה או תוצאות בדיקה.

המשתמש הגדיר מטרות, מגבלות ואישר שלבי מימוש ושמירה. Codex בדק מקורות וקוד, הציע פתרונות, כתב את הקוד והבדיקות והריץ את האימותים המתוארים. אין בכך טענה שהמשתמש כתב את הקוד בעצמו. תוצאות הרצה להלן מתייחסות לשלבים שבהם בוצעו; הן לא הורצו שוב במסגרת עריכת התיעוד הזאת.

להיסטוריה הקודמת ראו [PROMPT_LOG.md](PROMPT_LOG.md). היומן המקורי נשמר; עודכנו רק קישורי המסמכים בהקדמה. בפרט, נשמרה ההודעה ההיסטורית על פער תיעוד הרחבת הקטלוג, ללא המצאת פרומפט לשלב זה.

## 1. בדיקת אפשרויות לשילוב API ציבורי

- **מטרה:** למצוא API חינמי ללא מפתח, הקשור לאתר ההנצחה ומתאים למבנה רשימה–פרטים.
- **מה התבקש — סיכום:** לקרוא את קוד השירים והניתוב, להציע עד שתי אפשרויות, לבדוק CORS, קבצים מושפעים וסיכונים; ללא כתיבת קוד או שמירה ב־Git.
- **מה בוצע:** נבדקו SongList, SongPage, נתוני השירים ו־App; נבחנו שירות ההמרה ושירות Yahrzeit של Hebcal מול התיעוד הרשמי. הובחן בין קטלוג השירים המקומי לבין מקור API חיצוני.
- **בדיקות ותוצאה:** ניסיונות בקשות מהמסוף נחסמו עקב הרשאות רשת; לא הוצג הדבר כבדיקת CORS שעברה. הומלצה המרת תאריכים, עם הסתייגות ששילוב קטן באודות אינו מספק כשלעצמו Master–Detail מבוסס API. לא שונו קבצים בשלב הבדיקה.

## 2. התאמת Hebcal לל׳ בתשרי ולמנהג המשפחה

- **מטרה:** לשמור על דיוק וכבוד המשפחה בלי להפוך תוצאת API לקביעה הלכתית.
- **מה התבקש — סיכום:** לבדוק התאמה לפטירה בל׳ בתשרי תשפ״ו, 22.10.2025, א׳ דראש חודש חשוון, ולמנהג ספרדי; לבחון המרה בלבד ובדיקה בדפדפן, ללא שינוי קבצים.
- **מה בוצע:** התיעוד הרשמי ציין שחישוב Yahrzeit מבוסס על מנהג אשכנז. הומלץ להשתמש ב־converter בלבד ולהציג המרה של ל׳ בתשרי, ללא קביעת אזכרה או זמני שקיעה. לא נקבעה התאמה הלכתית של Yahrzeit למנהג המשפחה.
- **בדיקות ותוצאה:** בקשת המרה נפתחה בדפדפן והחזירה JSON עם 22.10.2025 עבור ל׳ בתשרי תשפ״ו וציון ראש חודש חשוון. זו הייתה פתיחת API ישירה, ולא בדיקת fetch או CORS מתוך האתר.

## 3. מימוש „תאריכים לזיכרון”

- **מטרה:** רשימת שנים ועמוד המרה ייעודי לכל שנה, תוך שמירת כל תוכן ההנצחה ומבנה השירים.
- **מה התבקש — סיכום:** להוסיף שנים מתשפ״ו, Link, React Router ו־useParams; לשלוף מ־Hebcal באמצעות fetch בתוך useEffect; להציג טעינה, שגיאה והצלחה, טיפוסים ללא any, קרדיט והבהרה שאין זו קביעת מועדי אזכרה. לא להתקין ספריות ולא לבצע commit לפני אישור נפרד.
- **מה בוצע:** נוספו שש שנים מתשפ״ו עד תשצ״א, /memorial-dates ו־/memorial-dates/:year, אימות תגובה, ניסיון נוסף וביטול בקשות. בוצעו התאמות ניווט וכותרת ומעט CSS. לא השתנה תוכן השירים, הביוגרפיה, התמונות, החידון או המועדפים.
- **בדיקות ותוצאה:** npm run build עבר. fetch אמיתי מתוך האתר ב־Chrome הצליח עבור תשפ״ו (22 באוקטובר 2025) ותשצ״א (27 באוקטובר 2030); כך אומתה גם גישה בין מקורות בסביבה שנבדקה. נוספו ארבעה תרחישי Playwright בשני גדלי חלון. כלל 48 הבדיקות עברו בהרצה עם Chrome מותקן ותצורה זמנית מחוץ למאגר; ההרצה הרגילה לא הושלמה בהצלחה בסביבה. פירוט והבחנה בין מענה מדומה לרשת אמיתית ב־[VALIDATION.md](VALIDATION.md).
- **שמירה:** לאחר בקשה נפרדת לבדיקת diff ושמירה, נוצר commit c1b2593 עם ההודעה `feat: add memorial date conversions using Hebcal API`. לא בוצע push.

## 4. הוספת Vitest ו־Vitest UI

- **מטרה:** לפחות חמש בדיקות יחידה בעלות ערך, לצד שמירת בדיקות Playwright.
- **מה התבקש — סיכום:** לבדוק תשתית קיימת, להתקין Vitest ו־@vitest/ui אם חסרים, לבדוק לוגיקה אמיתית, לאפשר UI, לוודא TypeScript ובנייה, ולהימנע משינוי התנהגות ומ־commit או push בשלב המימוש.
- **הבהרת הפקודות:** npm test ו־npm run test מפעילים את אותו סקריפט. הוגדר test להרצה חד־פעמית ו־test:ui לממשק במצב מעקב. פקודת בדיקות הדפדפן נשמרה כ־test:e2e.
- **מה בוצע:** הותקנו vitest@5.1.0 ו־@vitest/ui@5.1.0 כתלויות פיתוח. לוגיקת החיפוש והסינון ואימות תגובת ההמרה חולצו לפונקציות שהאתר משתמש בהן, ללא שינוי בתנאים. נוספו תצורת Vitest, בדיקת טיפוסי הבדיקות והפרדת איסוף הקבצים מ־Playwright.
- **בדיקות ותוצאה:** 14 בדיקות עברו בשני קבצים: שמונה לחיפוש/סינון וקטלוג ושש לאימות נתוני תאריך. npm test ו־npm run test עברו; Vitest UI נפתח בדפדפן והציג 14 הצלחות ואפס כישלונות. build ו־lint עברו. 48 בדיקות Playwright עברו עם Chrome מותקן ותצורה זמנית, על תוצר הבנייה. בדיקות היחידה אינן מבצעות בקשות רשת ואינן מוכיחות זמינות שירות חיצוני.
- **שמירה:** לאחר סקירת 12 הקבצים ואישור נפרד, נוצר commit 6634df3 עם ההודעה `test: add Vitest unit tests and UI`. לא בוצע push.

## 5. בדיקת מסמכי ההגשה ותיקונם

- **מטרה:** מסמכי הגשה התואמים למימוש ולתהליך האמיתי.
- **מה התבקש בבדיקה — סיכום:** לבדוק README.md, PRD.md, tasks.md ו־PROMPTS.md, שמות ומיקומים, פירוט API ו־Master–Detail, בדיקות ותיעוד AI; לא לשנות קבצים.
- **מה בוצע בבדיקה:** נקראו המסמכים והקוד הרלוונטי ונבדקו Git וקבצים מצורפים. נמצאו TASKS.md במקום tasks.md, היעדר PROMPTS.md ופרטי אפיון ובדיקות מיושנים. הבדיקה הייתה לקריאה בלבד ולא הורצו בה מחדש בדיקות תוכנה.
- **מגבלה:** „הוראות של יריב.docx” לא נמצא בפרויקט או בקבצים המצורפים הזמינים. הבדיקה הסתמכה על הדרישות שמסר המשתמש ולא הוצגה כאישור מול המסמך המקורי.
- **מה התבקש בתיקון — סיכום:** לתקן תיעוד בלבד, להשאיר README בשורש ושאר מסמכי ההגשה ב־docs, לשנות שם באמצעות Git, לשמור את היומן ההיסטורי, לתעד רק שלבים אמיתיים ולעדכן סתירות במסמכים המשלימים. ללא שינוי src/tests, commit או push.
- **הביצוע הנוכחי:** TASKS.md שונה ל־tasks.md דרך שם ביניים; מסמך זה נוסף; עודכנו README, PRD, משימות והמסמכים המשלימים. קישורי ההקדמה ביומן ההיסטורי הותאמו, בלי שינוי הרשומות ההיסטוריות. נבדקו 29 קישורי Markdown מקומיים, כולל התאמה מדויקת של אותיות השמות, וכולם תקינים. בדיקת diff לא מצאה שינויים ב־src, tests או public. תוצאות תוכנה לעיל שייכות לשלבי המימוש הקודמים; לא הורצו מחדש בדיקות תוכנה בשלב התיעוד. אין לסמן את התיעוד כשמור ב־commit או כמועלה לפני שבוצעו פעולות אלה באישור.
